# Forge Fitness v17.0.0 — Android Foundation

This release begins the permanent transition from the PWA architecture to a native Android application using Capacitor.

## Architecture
- `frontend/` — Forge UI and JavaScript application.
- `backend/` — current Python/FastAPI and training-intelligence services.
- `dist/` — generated native web bundle; PWA service worker and manifests are removed from native builds.
- `android/` — generated by Capacitor after dependencies are installed.
- `legacy_v16/` — untouched v16.0.1 source snapshot for migration/reference only.

## Native runtime boundaries
- `forge_native.js` detects web vs native runtime.
- Service-worker registration is disabled inside native builds.
- `forge_native_bridge.js` provides the first native capability bridge.
- `forge_api_config.js` separates the API endpoint from app assets.
- The Android package ID is `com.forgefitness.app`.

## First local setup
Requires Node.js, npm, Android Studio, and a JDK supported by the installed Android Gradle plugin.

1. `npm install`
2. `npm run sync:web`
3. `npx cap add android`
4. `npm run cap:sync`
5. `npx cap open android`

For a future non-Render API:
`node scripts/set-api-base.mjs https://YOUR-API-HOST`

Then:
`npm run cap:sync`

## Upgrade policy
The Android shell is treated as a stable container. Forge feature code stays modular inside `frontend/`. Native-only functionality belongs behind the native bridge. Cloud data schema and local-device schema must be independently versioned before local-first persistence is introduced.

## What this release deliberately does not do
- It does not remove the existing backend.
- It does not migrate the API off Render yet.
- It does not claim offline-native storage is complete.
- It does not generate a signed production APK without an Android SDK/signing environment.
